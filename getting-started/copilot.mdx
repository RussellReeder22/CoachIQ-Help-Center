## What Copilot is

Copilot is CoachIQ's built-in assistant. Describe the record you want to find or the change you want to make. It can look up saved product and scheduling details and prepare supported changes for review.

For an external assistant connected through MCP, follow [Use CoachIQ with AI](/getting-started/use-coachiq-with-ai) and [AI workflows](/settings/ai-workflows). The two experiences do not necessarily expose the same tools or controls.

## Look up information before changing it

Start with the exact product, scheduler, or availability name. If several records match, choose the intended one before continuing.

> What are the saved price, payment type, and credits for [product name]? Do not change anything.

For availability, ask for the saved weekly hours, timezone, and specific dates. A follow-up can refer to the record you just worked on, but check that the response still names the correct target.

## Prepare a supported change

| Task | Example request |
| --- | --- |
| Create a credit product | Create a one-time product named [name] for \$100 with four credits. Show the proposed settings before saving. |
| Change only a price | Change [product] from \$25 to \$30. Keep its credits, description, and all other settings unchanged. |
| Create a membership product | Create [name] at \$20 per month with no free trial. Do not subscribe or charge anyone. |
| Update weekly hours | Change Monday hours on [availability] to 10–11 AM in [timezone]. Preserve its other days and specific dates. |
| Add a specific date | Add [date] from 2–4 PM to [existing availability]. Preserve its weekly hours and do not create another template. |
| Create a scheduler | Create a free 30-minute lesson scheduler named [name] using [existing availability]. Keep self-booking, reminders, and calendar sync off. |

These are examples, not actions that run by reading this page. If information is missing, answer the clarification before approving a change.

## Review and approve

1. Read the proposed target and settings. For availability, check the dates, hours, and timezone; for products, check price, billing frequency, and credits.
2. Approve only the intended change. Decline or cancel a proposal that does not match your request.
3. Read the completion message and open the saved record to verify it. A conversational explanation alone is not proof that the change saved.
4. Ask for a read-only summary if you need to confirm what changed and what stayed the same.

Canceling a pending proposal does not undo something already saved. Check the record before requesting a correction.

## Inside builders

The **Copilot** panel in supported availability and booking builders helps fill structured settings from plain-language requests. Review the resulting fields and use that builder's **Save**, **Create**, or **Update** control to finish.

## Getting good results

Name the exact record, use concrete dates and times, and state what should remain unchanged. Work through one change at a time and check the saved result before building on it.

For a blackout, specify the template, date, hours, and timezone. For a scheduler, distinguish the new scheduler's name from the existing availability it should use.

## Common questions

<AccordionGroup>
  <Accordion title="The assistant asks me to choose a record">
    Confirm the intended match. Give the exact name or record identifier if the available choices are ambiguous. Do not approve a change to a different record just because its name is similar.
  </Accordion>
  <Accordion title="I reached a request limit">
    Follow the displayed retry countdown, then use **Try again**. Check the chat's outcome before sending the same change again; avoid duplicating work that already completed.
  </Accordion>
  <Accordion title="The saved result doesn't match my request">
    Open the affected record and check its actual settings. State the specific difference and ask for a correction that preserves the rest. Review that proposal before approving.
  </Accordion>
  <Accordion title="Can athletes use Copilot?">
    Copilot is a staff tool. Athletes continue to use the booking and account features provided to them in the portal or app.
  </Accordion>
</AccordionGroup>
